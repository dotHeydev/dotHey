# Introduction

AI coding agents are only as good as what they're told. Without a shared baseline, each session starts from scratch: the agent guesses your conventions, forgets last week's decisions, and drifts a little further from how your team works.

dotHey is that baseline. It's a lean kit of context, tools, and records that any agent, in any harness, with any model, reads the same way. You install it once, tell your agent about the project, and from then on you focus on what to build:

- **Envision** your product and its features.
- **Plan** how each idea looks, feels, and works.
- **Build** by instructing the agent, which follows the project's rules, standards, and workflow on its own.

## What you get

- **Context:** the project's product, rules, security, standards, and stack, one Markdown file per concern, written once and read by every agent.
- **Tools:** the `hey` command and a set of skills that do dotHey's work reliably: numbering records, linking files, checking decisions.
- **Work:** a workflow from specification to plan to failing tests to code, and records (features, decisions, notes, tasks, xrays) that outlive the chat.

## Principles

1. **Simplicity:** the smallest set of instructions that achieves the goal.
2. **Reliability:** instructions that produce the same behavior across sessions, harnesses, and models.
3. **Efficiency:** the least context, tokens, and steps an agent needs to do the right thing.

dotHey works out of the box for any project. What is specific to one tech stack or one harness comes as a [plugin](../extending/plugins.md).
